# עדכון מאגר העסקאות — תהליך בטוח

שלושה שלבים. רק השלב השלישי כותב למאגר שהאתר החי קורא ממנו, ורק אחרי שקראתם את הדוח.

## 1. איסוף לקובץ (מריצים בעצמכם, בטרמינל, מתיקיית הפרויקט)

```powershell
$env:DATA_TABLES="v2"; $env:HARVEST_OUT="data/harvest/2026-11/harvested.json"; npm run harvest
```

- נפתח Chrome ועובר שכונה אחרי שכונה, עם המתנה של 4 שניות בין שכונות. בערך 30–60 דקות.
- בסוף מודפס: `נשמרו N עסקאות ... שום מאגר לא שונה.`
- 0 עסקאות, או הרבה פחות מהצפוי: האתר חסם. מריצים שוב.

## 2. השוואה למאגר הקיים (קריאה בלבד)

```powershell
npx tsx scripts/harvest-compare.ts data/harvest/2026-11/harvested.json
```

הסקריפט כותב את `report.md` באותה תיקייה. בודקים בו:

- רוב העסקאות החדשות מתוארכות אחרי העסקה האחרונה במאגר (8.7.2026).
- 0 עסקאות שנכשלו בבדיקות התקינות, או מעט מאוד.
- `suspect.json`: עסקאות שנראות כמו מכירה קיימת עם מזהה אחר. הן לא עולות למאגר.

## 3. העלאה ועדכון מדד השוק

```powershell
npx tsx scripts/harvest-apply.ts data/harvest/2026-11
npx tsx scripts/harvest-apply.ts data/harvest/2026-11 --confirm
npx tsx scripts/build-market-index.ts --data data/harvest/2026-11/merged.json
```

- ההרצה הראשונה בודקת בלבד ולא כותבת. השנייה מכניסה רק את `added.json`. שורות קיימות לא משתנות ולא נמחקות.
- הסקריפט מסרב לרוץ אם מספר השורות במאגר החי שונה מהמאגר שאליו בוצעה ההשוואה.
- את `data/market-index.json` המעודכן מעלים לאתר עם commit, ובודקים לאחור על `merged.json` לפני שמעלים.
